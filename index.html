The idea

Make the hardware fault map part of backdoor construction.

Prior methods first choose useful model bits, then hope the hardware can realize them. ROBBIN reverses that order: it asks what each profiled DRAM page can actually do, then maps model pages accordingly.

01

Measure stable faults

Repeat effective hammering patterns and retain reproducible, direction-specific flips rather than probabilistic events.

02

Score realizable impact

Combine model-gradient sensitivity with FP32 or INT8 bit significance and the device vulnerability matrices.

03

Match pages greedily

For each high-value DNN page, test the top-K unused DRAM candidates and keep mappings that improve ASR while meeting the TA floor.

04

Deploy the mapping

Place model pages onto the selected vulnerable pages and replay the profiled aggressor patterns during the loaded inference session.

System implication

Keep model weights off profiled vulnerable pages.

Vulnerability-aware allocation restores clean accuracy and reduces ASR to the trigger-only baseline in the evaluated Device B configuration. The capacity cost depends on each device’s vulnerable-page density.

Abstract

Existing Rowhammer-based inference-time backdoor attacks design bit-flip strategies without accounting for the complete set of faults the underlying DRAM will produce. That disconnect makes attack behavior unreliable across devices and exposes models to damaging collateral flips.

ROBBIN integrates device-specific vulnerability profiles into backdoor construction, iteratively selecting model-to-DRAM page mappings that maximize triggered behavior while preserving clean accuracy.
